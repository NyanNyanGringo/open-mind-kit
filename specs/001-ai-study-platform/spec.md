# Feature Specification: AI Study Platform — Core Application

**Feature Branch**: `001-ai-study-platform`
**Created**: 2026-02-18
**Status**: Draft
**Input**: User description — локальное веб-приложение для обучения с AI-агентом, загрузкой файлов любых форматов, автоматической обработкой контента, карточками/тестами и дашбордом прогресса.

## Assumptions

- Приложение разворачивается локально через Docker Compose — пользователь запускает одну команду и открывает браузер.
- Все данные хранятся на машине пользователя; ничего не отправляется на внешний сервер без явного согласия.
- AI-агент используется для обработки контента (транскрипция, извлечение знаний, генерация вопросов) и интерактивного обучения.
- Поддерживаемые форматы: PDF, PPTX/PPT, DOCX/DOC, TXT, MD, MP3, MP4, MOV, WAV, M4A, PNG, JPG, JPEG, WEBP.
- «Элемент знания» — атомарная единица материала (слово, термин, факт, определение). Тип зависит от домена рабочего пространства.
- Механизм подключения AI-агента реализуется по образцу OpenClaw:
  - Для Codex/OpenAI — PKCE OAuth2 с локальным callback-сервером (`http://127.0.0.1:<port>/auth/callback`).
  - Для Anthropic/Claude Code — импорт токена через `claude setup-token` (paste-flow).
  - Учётные данные хранятся локально в зашифрованных JSON-файлах, организованных по agentId.
  - Токены обновляются автоматически с использованием файловых блокировок (без участия пользователя).

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Подключение AI-агента (Priority: P1)

Пользователь открывает приложение впервые, предоставляет учётные данные AI-провайдера и убеждается, что агент готов к работе.

**Why this priority**: Без подключённого агента невозможна обработка файлов и интерактивное обучение — блокирующая зависимость для всего приложения.

**Independent Test**: Пользователь подключает агента, загружает один текстовый файл и получает список извлечённых элементов знания.

**Acceptance Scenarios**:

1. **Given** пользователь открывает приложение в браузере,
   **When** выбирает AI-провайдера и вводит учётные данные,
   **Then** статус агента меняется на «Подключён», и загрузка файлов становится доступна.

2. **Given** агент подключён,
   **When** срок действия учётных данных истекает,
   **Then** приложение явно уведомляет пользователя и блокирует обработку — не падает молча.

3. **Given** пользователь вводит некорректные учётные данные,
   **When** нажимает «Подключить»,
   **Then** отображается понятная ошибка с указанием причины и ссылкой на то, где взять правильные данные.

### User Story 2 — Управление рабочими пространствами и уроками (Priority: P1)

Пользователь создаёт рабочее пространство (например, «Сербский язык») и организует материал по урокам.

**Why this priority**: Структура Workspace → Lesson является основной навигационной единицей; без неё невозможна сортировка контента и фильтрация обучения.

**Independent Test**: Пользователь создаёт рабочее пространство и два урока, переименовывает один, удаляет другой — все изменения сохраняются после перезагрузки страницы.

**Acceptance Scenarios**:

1. **Given** пользователь находится на главном экране,
   **When** создаёт рабочее пространство с названием и опциональным описанием,
   **Then** оно появляется в списке и остаётся после перезагрузки.

2. **Given** открыто рабочее пространство,
   **When** пользователь создаёт урок с названием,
   **Then** урок появляется в упорядоченном списке внутри рабочего пространства.

3. **Given** урок существует,
   **When** пользователь переименовывает или удаляет его,
   **Then** изменение немедленно отражается в интерфейсе и сохраняется.

### User Story 3 — Загрузка и автоматическая обработка файлов (Priority: P1)

Пользователь перетаскивает или выбирает файлы в урок; система автоматически их обрабатывает и извлекает элементы знания.

**Why this priority**: Ключевая ценность — «закинул и забыл». Без этого нет контента для обучения.

**Independent Test**: Пользователь загружает PDF-лекцию и аудиозапись в один урок; через разумное время видит список элементов и может начать карточную сессию.

**Acceptance Scenarios**:

1. **Given** выбран урок и агент подключён,
   **When** пользователь перетаскивает файл поддерживаемого формата,
   **Then** файл принимается, отображается индикатор прогресса обработки.

2. **Given** файл загружен,
   **When** агент завершает обработку,
   **Then** пользователь видит список извлечённых элементов знания без дополнительных действий.

3. **Given** загружен аудио- или видеофайл,
   **When** обработка завершена,
   **Then** доступна транскрипция и список элементов, извлечённых из неё.

4. **Given** загружен файл неподдерживаемого формата,
   **When** попытка его принять,
   **Then** отображается ошибка с перечнем поддерживаемых форматов.

5. **Given** обработка файла завершилась с ошибкой,
   **When** пользователь открывает урок,
   **Then** ошибка отображена явно для конкретного файла; остальные файлы не затронуты.

### User Story 4 — Обучение через карточки и тесты (Priority: P2)

Пользователь запускает сессию обучения: карточки или тест с выбором материала (конкретные уроки, диапазон, «слабые места»).

**Why this priority**: Основная механика практики. Без неё приложение является только просмотрщиком файлов.

**Independent Test**: Пользователь запускает карточную сессию по урокам 1 и 2, проходит 10 карточек, получает результат; слабые карточки помечаются и появляются в фильтре «слабые места».

**Acceptance Scenarios**:

1. **Given** в рабочем пространстве есть урок с обработанными элементами,
   **When** пользователь запускает карточную сессию с фильтром «Урок 1 + Урок 2»,
   **Then** показываются карточки только из этих уроков в случайном порядке.

2. **Given** запущена сессия,
   **When** пользователь отмечает карточку «Знаю» или «Не знаю»,
   **Then** результат записывается и влияет на рейтинг знания элемента.

3. **Given** пользователь выбирает фильтр «Слабые места»,
   **When** запускает сессию,
   **Then** показываются только элементы с низким рейтингом знания.

4. **Given** завершена сессия,
   **When** пользователь видит экран результатов,
   **Then** отображаются: процент правильных ответов, количество карточек, кнопка «Повторить слабые».

---

### User Story 5 — Дашборд прогресса (Priority: P2)

Пользователь видит визуализацию своего прогресса: по рабочим пространствам, урокам, элементам знания.

**Why this priority**: Дашборд мотивирует и позволяет осознанно планировать дальнейшее обучение.

**Independent Test**: После 3 сессий пользователь открывает дашборд и видит: общий прогресс, график активности по дням, топ слабых элементов.

**Acceptance Scenarios**:

1. **Given** пользователь провёл хотя бы одну сессию,
   **When** открывает дашборд,
   **Then** видит количество изученных элементов, процент освоения, историю сессий.

2. **Given** открыт дашборд,
   **When** пользователь выбирает конкретное рабочее пространство,
   **Then** статистика фильтруется только по нему.

3. **Given** открыт дашборд,
   **When** пользователь смотрит на список элементов,
   **Then** элементы отсортированы по рейтингу знания (слабые — первые).

---

### User Story 6 — Чат-сессия с агентом (Priority: P3)

Пользователь ведёт свободный диалог с AI-агентом в контексте выбранных уроков, включая игровые форматы.

**Why this priority**: Дополняет карточки вариативностью, но не является блокирующим для MVP.

**Independent Test**: Пользователь открывает чат по «Уроку 1», задаёт вопрос по материалу, получает ответ, основанный на контенте этого урока.

**Acceptance Scenarios**:

1. **Given** выбран урок с обработанным контентом,
   **When** пользователь открывает чат и задаёт вопрос,
   **Then** агент отвечает, опираясь на материалы этого урока.

2. **Given** открыт чат,
   **When** пользователь просит игровой формат (например, «угадай слово по описанию»),
   **Then** агент ведёт игру в чат-интерфейсе без переключения контекста.

### Edge Cases

- Что если загружается файл >500 МБ? — Система ОБЯЗАНА показать предупреждение о лимите и отклонить загрузку.
- Что если несколько файлов загружаются одновременно? — Прогресс каждого отображается отдельно; ошибка одного не блокирует остальные.
- Что если агент недоступен во время карточной сессии? — Сессия продолжается (данные локальные); функции, требующие агента (чат), блокируются с понятным сообщением.
- Что если пользователь удаляет рабочее пространство с данными? — Запрашивается явное подтверждение с указанием числа уроков и файлов, которые будут удалены безвозвратно.
- Что если два файла в уроке содержат дублирующийся контент? — Агент дедуплицирует элементы знания (или помечает дубликаты для ревью).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ОБЯЗАНА разворачиваться локально единственной командой (например, `docker compose up`).
- **FR-002**: Система ОБЯЗАНА поддерживать подключение AI-агента по паттерну OpenClaw:
  PKCE OAuth2-поток с локальным callback-сервером для Codex/OpenAI;
  paste-flow (`claude setup-token`) для Anthropic/Claude Code;
  зашифрованное локальное хранение токенов с автоматическим обновлением;
  явный статус подключения (подключён / истёк / ошибка) всегда виден в интерфейсе.
- **FR-003**: Пользователи ОБЯЗАНЫ иметь возможность создавать, переименовывать и удалять рабочие пространства.
- **FR-004**: Пользователи ОБЯЗАНЫ иметь возможность создавать, переименовывать и удалять уроки внутри рабочего пространства.
- **FR-005**: Система ОБЯЗАНА принимать файлы форматов: PDF, PPTX, DOCX, TXT, MD, MP3, MP4, MOV, WAV, M4A, PNG, JPG, JPEG, WEBP.
- **FR-006**: Система ОБЯЗАНА автоматически извлекать текстовый контент из всех загруженных файлов (транскрипция аудио/видео, парсинг документов, распознавание текста на изображениях) без ручных действий пользователя.
- **FR-007**: Система ОБЯЗАНА структурировать извлечённый контент в элементы знания и сохранять их в локальное хранилище.
- **FR-008**: Пользователи ОБЯЗАНЫ иметь возможность запускать карточные сессии с фильтрацией по: конкретным урокам, диапазону дат, всем материалам, слабым местам.
- **FR-009**: Система ОБЯЗАНА записывать результат каждого ответа и пересчитывать рейтинг знания элемента.
- **FR-010**: Система ОБЯЗАНА предоставлять дашборд с: общим прогрессом, историей сессий, рейтингом элементов по уровню знания.
- **FR-011**: Пользователи ОБЯЗАНЫ иметь возможность вести диалог с агентом в контексте выбранных уроков.
- **FR-012**: Система ОБЯЗАНА работать полностью локально после первоначальной настройки; данные пользователя ЗАПРЕЩЕНО отправлять на внешние серверы без явного согласия.
- **FR-013**: Система ОБЯЗАНА отображать статус обработки каждого файла: в очереди / обрабатывается / готово / ошибка.

### Key Entities

- **Workspace**: Рабочее пространство для темы обучения. Атрибуты: название, описание, дата создания.
- **Lesson**: Урок внутри рабочего пространства. Атрибуты: название, порядковый номер, дата создания.
- **SourceFile**: Загруженный файл. Атрибуты: оригинальное имя, формат, размер, статус обработки.
- **KnowledgeItem**: Атомарная единица знания. Атрибуты: содержание, контекст (источник), урок, рейтинг знания.
- **LearningSession**: Сессия обучения. Атрибуты: тип (карточки/тест/чат), дата, фильтр, итоги.
- **PerformanceRecord**: Результат ответа на элемент. Атрибуты: элемент, сессия, результат (верно/неверно), дата.
- **AgentConfig**: Настройки подключения агента. Атрибуты: провайдер, зашифрованные учётные данные, статус.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь разворачивает приложение с нуля менее чем за 5 минут, следуя README.
- **SC-002**: PDF-файл до 50 МБ обрабатывается и готов к использованию менее чем за 60 секунд.
- **SC-003**: Аудио/видеофайл длительностью до 30 минут транскрибируется, элементы доступны менее чем за 5 минут.
- **SC-004**: Карточная сессия по 20 элементам запускается без заметной задержки после выбора уроков.
- **SC-005**: 90% пользователей успешно подключают AI-агента с первой попытки, следуя onboarding-инструкции.
- **SC-006**: Дашборд загружается менее чем за 2 секунды при истории до 1 000 сессий.
- **SC-007**: После удаления рабочего пространства в локальном хранилище не остаётся данных, связанных с ним.

## Design Decisions

### AI Agent Connection: OpenClaw OAuth2 Pattern (resolved)

Механизм подключения агента реализуется по образцу проекта [OpenClaw](https://github.com/openclaw/openclaw):

| Провайдер | Механизм | Детали |
|-----------|----------|--------|
| Codex / OpenAI | PKCE OAuth2 | Локальный callback `http://127.0.0.1:<port>/auth/callback`; при недоступности порта — paste-flow |
| Anthropic / Claude Code | Setup-token paste-flow | Пользователь выполняет `claude setup-token`, вставляет токен в UI |
| Будущие провайдеры | Расширяемый plugin-интерфейс | Каждый провайдер реализует единый AuthProvider-интерфейс |

Хранение: зашифрованные JSON-файлы, организованные по `agentId`.
Обновление токенов: автоматическое, с файловыми блокировками во избежание конфликтов.
